# 品質監査 2026-09-15

## 結論の範囲

今回の変更を含むローカル実装で、単体3スイートとEdgeヘッドレスの576実行ケース、6画面サイズの実行ボタン操作確認に合格。
これは「テスト不要」「全環境で不具合ゼロ」を意味しない。実機スマホのソフトキーボード、実言語処理系との完全互換性、全手入力パターン、教材の教育効果は未検証。

## 今回新たに修正した問題

1. 教材構文の二重変換で `var var` / `let let` / `$$` / `;;` が発生する経路を修正。46階の変数参照に必要な周辺変数は別途引き継ぐ。
2. コメント・文字列に構文名を書くだけで課題の必須構文判定を通過できる問題を、解析済み命令／式の検査へ変更。
3. 実行されない分岐内の命令を実行済みと扱わないよう、クリア時に実行した構文を照合。
4. 波かっこの閉じ忘れ・余分な閉じかっこ・対応のないelse・未知のブロックを拒否。
5. forの初期化・比較・更新で異なる変数を使う誤記を拒否。
6. 閉じ波かっこ以降のエラー行番号がずれる問題を修正。
7. 文字列内のtrue/false、演算子、変数記号、メソッド風文字列を変換してしまう問題を修正。
8. 深い入れ子の繰り返しが巨大な実行配列を作る問題に展開数上限を追加。
9. Pythonの対応のないelseが黙って無視される経路を拒否。
10. JSONとして読めても形式が不正な進捗で起動／再開が壊れる問題を修正。
11. 変数代入の見本にふりがながない問題を修正。識別子の一部や文字列の中に誤ってふりがなを付けない。
12. Javaの文字列比較の教材をequalsへ修正。
13. Java/JavaScriptの47階で分岐の内側で宣言したresultを外側から使っていた問題を修正。
14. 現状と違う旧引き継ぎ書を履歴資料へ移し、目的・全48階・4モード・制約・検証範囲を更新。

## 検証内訳

- `tests/levels.test.cjs`: 既存のマップ・課題値・文言テスト。
- `tests/language-modes.test.cjs`: 必須構文のcontextも渡して4言語48階を解析。実ソース行番号と動作の比較を分離。
- `tests/audit-regressions.test.cjs`: 今回の再発防止（文字列保持、コメント迂回、構文例、ブロック、行番号、展開上限、文字列比較、変数宣言）。
- `tests/browser-audit.cjs`: 4×48×2=384回、一括実行は実行ボタンクリック、一段階実行は実際のハンドラーで検証。ランダム18〜23階は4×6×8=192回。計576回。
- 1920×1080、1366×768、1024×600、800×600、390×844、844×390で実行ボタンが画面内かつクリック可能。
- タイトル4言語選択肢・デバッグ48ボタン・保存進捗再読み込み・4種の不正保存データ。
- ブラウザー未処理例外なし。構文チェックとgit diff --checkも実施。

## 残る確認・設計課題

- 実機スマホのキーボード表示、ズーム、読み上げなどの確認は未実施。
- 簡易処理系と標準言語の意味論には差がある。教材外の式や構文まで正しく動くとは扱わない。
- ブラウザーの保存禁止／容量超過時の書き込み、途中編集・画面遷移の実行キャンセルなど、正常系外の操作は追加監査が必要。
- すべてのヒント・文言の教育的妥当性を人間の理解度まで含めて評価したわけではない。
- 既存解答の一元管理と配布Excelの更新経路は本監査の修正対象に含めていない。

この残件があるため、本監査をもってアプリ全体の無条件の完成宣言はしない。
